# 드럼스코어 · 스템 분리 + AI 채보

음악 파일에서 **드럼 스템(stem)**을 분리하고, 학습된 드럼 채보 모델로 타격 시점을 찾습니다. 분리된 드럼 듣기, 원곡 비교 재생, WAV 저장, 악보 편집, MIDI/MusicXML/프로젝트 내보내기를 지원합니다.

- [개발 인수인계](HANDOFF.md): 구조, 완료한 수정, 검증 결과, 미완료 사항과 다음 작업 순서
- [새 채팅에 붙여 넣을 요청문](NEXT_CHAT_PROMPT.md)
- [개인 연결 설정 예시](engine/private-access.example.json): 실제 연결 정보는 GitHub에 포함하지 않습니다.

이 저장소는 소스 백업입니다. 개인 앱은 맥의 로컬 엔진과 Tailscale Serve로 실행하며 GitHub Pages 주소에서는 AI 엔진을 실행할 수 없습니다. 최초 설치 때 필요한 오픈소스 패키지·모델 다운로드와 앱의 실제 서비스 운영은 구분합니다.

## 실행

macOS에서 `start.command`를 실행합니다. Python 3.10~3.12와 Git이 필요합니다. Codex의 번들 Python이 있는 경우 자동으로 찾아 사용합니다. 처음 실행은 전용 `engine/.venv`에 라이브러리를 설치합니다. 첫 AI 분석 때 약 80MB의 Demucs 가중치를 내려받습니다. 설치 후에는 `http://127.0.0.1:8765/`에서 실행합니다. 터미널 창을 열어 두고 사용하세요. Ctrl+C로 종료할 수 있습니다.

터미널에서 실행하려면:

```sh
python3.12 start-engine.py
```

Windows/Linux에서도 Python 3.10~3.12와 Git을 설치한 뒤 위 Python 스크립트를 사용할 수 있습니다. macOS Apple Silicon/CPU에서 검증했으며 Windows/CUDA는 별도 검증하지 않았습니다. FFmpeg는 `imageio-ffmpeg`의 바이너리를 사용하므로 별도 설치가 필요 없습니다.

## 사용 방법

1. MP3/WAV/M4A/FLAC 등의 곡을 선택하고 `AI 드럼 분리 + 채보`를 선택합니다. 브라우저가 해당 형식을 디코딩할 수 있어야 미리 듣기와 파일 로딩이 가능합니다.
2. 원곡이면 ‘이미 드럼만 있는 파일’을 끕니다. 외부 프로그램에서 분리한 드럼 스템을 넣었다면 체크해서 분리를 생략할 수 있습니다.
3. `드럼 악보 만들기`를 누릅니다. 12분·220MB 이하 파일을 처리하며, CPU에서는 곡 길이보다 오래 걸릴 수 있습니다. 진행률은 오디오 구간 처리에 맞춰 갱신됩니다. 취소는 현재 구간 처리 후 반영됩니다.
4. `원곡`과 `분리된 드럼`을 전환해 같은 위치에서 비교 재생합니다. `드럼 WAV 저장`으로 스템을 내보냅니다.
5. BPM의 절반/두 배 해석, 박자와 마디 첫 위치를 확인합니다. BPM을 직접 입력하면 이후 채보에서도 유지됩니다. ‘자동’으로 돌아가면 검출된 박자 지도를 사용합니다. 위치 보정은 ms 단위입니다.
6. 탐·심벌 등 주황색 확인 음표를 듣고 편집합니다. BPM/위치 재정렬은 수동 추가 및 AI 음표 삭제를 유지합니다. 재분석은 새 악보를 만듭니다.

## 두 종류의 MIDI

- **연주 MIDI · AI 검출 원본**: 검출된 모든 타격의 초 단위 시점을 보존합니다. 셋잇단음표·스윙·16분음표보다 빠른 연타도 격자에 강제로 맞추지 않습니다. 상대적 강도를 velocity로 저장합니다. 수동 편집과 난이도 필터는 반영하지 않습니다.
- **악보 MIDI / MusicXML**: 화면의 16분음표 격자, 난이도 필터, 수동 편집을 반영합니다. 현재 내보내기는 하나의 대표 BPM으로 작성되므로 실제 연주의 템포 변화는 연주 MIDI로 보존하세요.

프로젝트 파일에는 AI 검출 원본, 박자 지도, 수동 수정이 저장됩니다. 음원과 드럼 WAV는 포함되지 않으므로 별도로 보관해 주세요. 파일을 다시 선택하면 새 곡으로 시작합니다.

## 창 전환 · 새로고침 후 이어하기

AI 분석은 맥의 작업으로 실행됩니다. **업로드가 끝난 뒤에는 다른 창을 보거나 앱 창을 닫아도** 맥에서 분리·채보가 계속됩니다. 같은 브라우저에서 다시 열면 같은 작업 번호에 자동으로 재연결하며 새 분석을 중복 요청하지 않습니다. 통신이 잠깐 끊겨도 자동 취소하지 않고 연결 복구를 기다립니다. ‘분석 취소’를 직접 눌렀을 때만 취소를 요청합니다.

원곡과 드럼 WAV는 브라우저의 IndexedDB에, 작업 번호와 편집 악보는 기기에 자동 저장합니다. 완료 후 재접속하면 음원·악보·수동 BPM/편집을 복구합니다. 이 자동 저장은 다운로드하는 프로젝트 JSON과 별개입니다. 브라우저 사이트 데이터를 지우면 자동 저장도 없어지며, 시크릿 모드·저장 공간 부족·기기의 캐시 정리 시 복구가 제한됩니다. 민감한 음원을 사용한 뒤에는 필요한 파일을 내려받고 해당 사이트의 저장 데이터를 삭제하세요.

다른 기기나 처음 사용하는 브라우저에서는 맥의 최근 작업을 찾아 결과에 연결할 수 있지만, 원곡과 수동 편집은 그 브라우저에 저장된 내용만 복구합니다. 맥이 꺼지거나 엔진 자체가 재시작되면 진행 중인 추론은 이어서 계산할 수 없습니다. 완료 결과는 보관 기간 동안 엔진 재시작 후에도 복구됩니다. `빠른 채보 · 브라우저 분석`은 맥의 백그라운드 AI 작업이 아닙니다.

## 모델과 실제 지원 범위

- 분리: [Demucs v4](https://github.com/facebookresearch/demucs), 공식 `htdemucs_ft` 앙상블 중 드럼 전문 모델 `f7e0c4bc`. 공식 앙상블에서 이 모델만 드럼 출력에 가중치 1을 받으므로 드럼과 무관한 나머지 모델 세 개는 실행하지 않습니다. 24초 구간, 양쪽 2초 문맥, 내부 6초 분할과 50% 겹침을 사용합니다.
- 채보: [ADTOF](https://github.com/MZehren/ADTOF)의 [PyTorch 포트](https://github.com/xavriley/ADTOF-pytorch), 커밋 `85c192e78f716ea0b111cc8a5ee4a8f6a3a4f8a9`. 100fps, 20초 구간에 양쪽 2초 문맥, 구간 경계에서 중복을 제거한 뒤 전체 활성도에서 피크를 검출합니다. 학습 가중치가 없거나 모델과 맞지 않으면 오류로 중단합니다.
- 자동 분류는 **킥·스네어·하이햇·탐·심벌의 5종**입니다. 탐의 높이, 오픈/클로즈 하이햇, 라이드/크래시는 모델이 직접 구분하지 못합니다. 탐/심벌은 포괄 음표로 표시하고 수동 확인합니다. 탐 MIDI 47, 심벌 MIDI 49는 포괄 그룹의 대표 음색이며 세부 종류를 확정한 결과가 아닙니다.
- 음표에 표시되는 수치는 모델 활성도이며, 정확도 확률로 보정된 수치는 아닙니다. Velocity는 분리된 전체 드럼 스템의 짧은 RMS에서 추정하므로 동시에 친 다른 드럼의 영향을 받을 수 있습니다.
- 악보 표시는 현재 16분음표까지입니다. 격자에서 벗어난 타격과 한 칸에 겹친 연타 수를 보고합니다. 마디 첫 박자는 사용자가 확인해야 합니다.
- 학습된 모델을 사용해도 모든 곡의 전문가 수준 정확도를 보장하지 않습니다. 장르·믹싱·잔향·필인에 따라 확인이 필요하며, 실제 사용자 곡의 정답 악보와 비교한 정확도 평가는 아직 하지 않았습니다.

## 스마트폰 → 개인 연결 → 맥 처리

UI와 API는 같은 주소에서 제공됩니다. 스마트폰의 `localhost`로 잘못 연결하지 않으며, GitHub Pages나 GitHub 저장소를 실행 경로에 사용하지 않습니다. GitHub는 소스 백업용입니다.

개인 원격 접속은 **Tailscale Serve**를 사용합니다. 맥과 스마트폰을 같은 Tailscale 계정에 연결하고, 맥의 개인 HTTPS 주소로 접속합니다. 공용 인터넷에 공개하는 Funnel은 사용하지 않습니다. 음원은 개인 연결로 맥에 전송되며 분리·채보는 맥에서 수행합니다. 서버 요금이나 유료 AI API 키는 필요하지 않습니다. 맥이 꺼져 있거나 잠들거나, Tailscale이 끊기면 원격 접속도 멈춥니다.

설치 담당자는 `engine/.private-access.json`에 해당 맥의 정확한 Tailscale HTTPS `origin`과 소유자 `login`을 설정합니다. 파일은 Git/배포 ZIP에 포함하지 않습니다. 서버는 `127.0.0.1`에만 바인딩하고 `--no-proxy-headers`로 실행해야 합니다. 허용된 소유자의 `Tailscale-User-Login`을 가진 Serve 요청만 받으며, 다른 계정·인증 없는 프록시·Funnel 요청은 거부합니다. 임의 와일드카드 Host/CORS는 허용하지 않습니다.

```sh
tailscale serve --bg --https=443 http://127.0.0.1:8765
```

처음에는 Tailscale 로그인 및 HTTPS/Serve 승인이 필요할 수 있습니다. 이미 다른 서비스가 443을 사용한다면 덮어쓰지 말고 별도 포트나 경로를 선택하세요. `--bg` 설정은 Tailscale 재시작 후에도 유지됩니다.

이 맥의 자동 실행용 복사본은 `~/Library/Application Support/DrumScoreStudio`에, 사용자 LaunchAgent는 `~/Library/LaunchAgents/com.kimkirik.drum-score-studio.plist`에 설치합니다. macOS 로그인 뒤 자동 시작하고 비정상 종료 시 재시작합니다. 로그는 `~/Library/Logs/DrumScoreStudio`에 있습니다. 소스 수정 후 UI 파일(`index.html`, `styles.css`, `app.js`, `pro-client.js`, `timing.js`, `workspace-store.js`)과 `engine/server.py`, `engine/pipeline.py`, `engine/private_access.py`를 복사본에 동기화한 뒤, 진행 중인 채보가 없을 때만 서비스를 다시 시작하세요. 맥 전원 종료·로그아웃 중에는 실행되지 않습니다.

Tailscale Serve의 [공식 설명](https://tailscale.com/docs/features/tailscale-serve)과 [백그라운드 실행 동작](https://tailscale.com/docs/reference/tailscale-cli/serve)을 참고하세요.

분석 중 업로드 사본과 임시 오디오는 `engine/.jobs`에 만들어지고 완료/실패/취소 후 입력 사본은 지워집니다. 성공한 드럼 WAV·MIDI·JSON은 24시간이 지난 뒤 **다음 분석 요청 때** 정리됩니다. 완료 결과와 작업 메타데이터는 엔진 재시작 후 복구됩니다. 기기에 저장한 원곡·악보·드럼 캐시는 별도이므로 브라우저 사이트 데이터 삭제 전까지 남을 수 있습니다. 엔진 정적 라우트는 UI 파일만 제공합니다. 캐시와 업로드는 Git에 포함되지 않습니다.

`빠른 채보`는 기존 브라우저 신호 분석 기능입니다. AI 연결 실패 시 자동으로 빠른 채보 결과를 대신 제공하지 않습니다. 샘플 버튼도 실제 분석 경로를 통과하며 미리 작성한 정답 악보를 주입하지 않습니다.

## 검증

```sh
node --test engine/tests/*.test.cjs
engine/.venv/bin/python engine/tests/test_pipeline.py
engine/.venv/bin/python engine/tests/test_pipeline.py --real-models
engine/.venv/bin/python -m pip install -r engine/requirements-test.txt
engine/.venv/bin/python engine/tests/test_server.py
engine/.venv/bin/python engine/tests/test_private_access.py
```

타이밍 검증은 가변 박자·선행 무음·동시 타격·충돌 보고·수동 BPM/위치를 확인합니다. Python 검증은 무음, 잘못된 오디오, 수동 BPM, 취소, 연타/동시 타격 MIDI를 확인합니다. `--real-models`는 생성한 6초 혼합 음원을 실제 Demucs와 ADTOF에 통과시켜 드럼 WAV 길이, 타격 생성, MIDI 저장을 확인하는 실행 검증입니다. 이 테스트의 타격 수는 실제 음악 정확도 벤치마크가 아닙니다.
