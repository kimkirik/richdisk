# 물때 우선 표시 및 로딩 재점검 · 2026-09-07

이 문서는 공개 반영 전에 수행한 구현·로컬 검증 기록입니다. 공개 서버와 GitHub 화면은 함께 배포하며, 실제 공개 응답 시간은 로컬 시험값과 구분해야 합니다.

## 첫 화면 동작
- 만조·간조 시각과 예측 물높이를 앱 맨 위에 표시합니다.
- 같은 장소·날짜에서 확인했던 물때는 재실행 시 API 응답을 기다리지 않고 표시합니다. 원자료 조회 시각, 저장 자료 여부와 최신 확인 상태를 함께 표시합니다.
- 저장 범위는 최대 6시간·24건입니다. 날짜·장소·자료 시각·교차하는 고저조·숫자 형식을 확인합니다. 좌표형 확인 중인 임시 기준항 응답은 저장하지 않습니다.
- 저장된 날씨나 점수는 복원하지 않습니다. 처음 방문하거나 아직 확인하지 않은 날짜·장소에는 새 API 조회가 필요하므로 모든 첫 방문의 즉시 표시를 보장하지는 않습니다.
- 표시 값은 조석예보이며 현재 현장 수위를 실측한 값이 아닙니다.

## 공개 지연 재현
9월 7일 자료 재측정: 꾸지나무골 17.377초(물때 있음), 신두리 19.011초(물때 없음), 안흥 17.494초(물때 없음). 이는 전체 API 응답 소요 시간이며 물때 제공기관만의 응답 시간은 아닙니다. 로그에서도 11.510초 후 취소된 전체 조회를 확인했습니다.

## 서버 개선
- 좌표형 자료를 기다린 뒤 기준항 조회를 시작하던 구조를 바꿔 둘을 동시에 조회합니다. 먼저 받은 기준항 물때는 인근 참고·확인 중으로 표시하고 좌표형 성공 시 갱신합니다.
- 늦게 도착한 기준항이 이미 완료된 좌표형 물때를 덮어쓰지 않습니다.
- 선택 날짜의 좌표형 자료가 실패하면 전날·다음날의 응답까지 불필요하게 기다리지 않습니다.
- 같은 기준항·날짜의 검증된 조석은 10분 캐시와 동시 조회 공유를 사용합니다. 날씨 실패나 장소 변경으로 같은 물때를 다시 받아오지 않습니다. 원자료 조회 시각은 유지합니다.
- 좌표형 API 권한 실패 후 영구적으로 사용을 중지하던 상태를 5분 후 재확인하도록 수정했습니다.

## 검증 결과
- 서버 자동 테스트 47개 통과. 프런트 공통 테스트 17개 통과(서버 테스트와 중복).
- TypeScript 검사, 서버·프런트 빌드, 변경 파일 공백 검사 통과.
- 실제 빌드한 서버에 기준항 60ms·좌표형 700ms 지연과 날씨 실패를 주입한 시험에서 첫 물때 111ms, 전체 완료 1951ms. 실제 공개 서버 속도 측정값이 아닙니다.
- 두 해변이 같은 기준항을 조회할 때 외부 물때 요청은 1회로 공유됩니다. 캐시 만료·날짜 분리·자료 시각 유지·좌표형 우선순위·권한 회복을 확인했습니다.
- 실제 빌드한 서버에 검증용 자료를 공급한 브라우저 테스트: 물때를 저장한 다음 API를 의도적으로 503으로 차단하고 재실행해도 물높이가 표시됩니다. 다른 날짜로 변경하면 이전 물높이가 사라집니다. 달력에도 저장 물때가 표시되며 대기 오버레이로 가리지 않습니다.
- 390px 모바일에서 물높이 카드가 화면 위 78~320px 안에 표시됩니다. 320·390·1440px에서 가로 넘침 없음. 확인한 브라우저의 앱 오류 로그 없음. 검증 화면의 조석 수치는 테스트용이며 실제 예보가 아닙니다.

## 반영 후 확인
공개 서버의 스트리밍 전달 여부와 최초 방문의 실제 물때 도착 시간은 배포 후 다시 확인해야 합니다. 저장 자료가 없는 상태에서 제공기관까지 느리거나 실패하면 이번 수정만으로 즉시 표시할 수는 없습니다.
