# 날씨 로딩 개선 · 2026-09-07

이 문서는 공개 반영 전에 수행한 구현·로컬 검증 기록입니다. 실제 공개 성능과 테스트 지연값을 구분해 읽어 주세요.

## 확인된 지연
공개 API에서 9월 7일 자료를 조회했을 때 꾸지나무골 17.407초, 신두리 19.380초가 걸렸습니다. 두 응답 모두 날씨는 있었지만 물때와 최근 강수는 미확인이었습니다. 서버가 날씨·물때·최근 강수 작업 전체를 기다린 뒤 한 번에 응답하던 구조였습니다. 이 두 번의 측정은 평균이나 장기 통계가 아닙니다.

## 수정
- 선택 장소와 달력은 도착한 자료부터 전달하는 스트리밍 응답을 사용합니다.
- 물때 전에는 선택 날짜의 제공 예보로 명시하고, 물때 도착 후 실제 간조 시간대에 맞춰 다시 계산합니다.
- 참고점수·시야·활동 판정은 전체 조회 완료까지 보류합니다.
- 동일 장소·날짜 동시 요청은 하나의 조회를 공유합니다. 늦게 접속한 사용자도 이미 도착한 날씨를 전달받습니다.
- 날짜·장소·자료 시각 검증, 불완전 응답 거절, 기존 JSON API 호환을 유지합니다.

## 검증
- 서버 자동 테스트 39개 통과. 프런트 공통 테스트 14개 통과(서버 테스트와 중복).
- 서버 및 프런트 TypeScript 검사와 배포 빌드 통과.
- 실제 빌드한 API에 날씨 50ms, 물때 600ms, 최근 강수 1200ms의 인위적 지연을 주입: 날씨 첫 전달 110ms, 전체 완료 1260ms. 이는 실제 공개 서버의 개선 속도가 아닙니다.
- 스트림 중단, UTF-8 분할 응답, 동시 요청 공유 및 최종 JSON 캐시 재사용 확인.
- 브라우저에 별도 지연 자료를 공급해 날씨 선표시와 최종 갱신 확인. 확인 화면의 앱 콘솔 오류 0건, 가로 넘침 없음. 이 브라우저 자료는 화면 검증용 가상 자료입니다.

## 남은 확인
공개 서버와 GitHub 화면을 함께 반영한 뒤 실제 연결에서 첫 날씨 도착 시간을 다시 측정해야 합니다. 제공기관 자체의 날씨 응답 지연은 이번 수정만으로 제거되지 않습니다. 배포 경로의 스트리밍 전달 여부도 공개 반영 후 확인이 필요합니다.
